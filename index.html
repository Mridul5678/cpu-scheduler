CPU scheduling formulas

Per-process timing

  • Turnaround time (TAT) = Completion time − Arrival time
  • Waiting time (WT) = Turnaround time − Burst time
  • Response time (RT) = First CPU start time − Arrival time
  • CPU utilisation = Process execution timeTotal time × 100% (useful work only)
  • Switch overhead = Context switches × switch costTotal time × 100% — utilisation + switch overhead + idle = 100% of the total time.
  • Context switch: counted each time the CPU starts a different process from the one it last ran (including after an idle gap); the first dispatch is not a switch.
  • Throughput = Processes completedTotal time

Fairness and selection rules

  • Jain's fairness index: J = (Σ xi)2n · Σ xi2 where xi = TATi / BTi. Ranges from 1/n to 1.
  • Highest Response Ratio Next (HRRN): R = W + SS = 1 + WS Waiting jobs gain priority over time, which prevents indefinite postponement.
  • Time quantum heuristic: q is the 80th percentile of the burst times (nearest-rank: sort the bursts and take the one at position ⌈0.8 · n⌉), so at least 80% of CPU bursts finish within one quantum.

How to demonstrate and explain the project to evaluators

ScheduleX Pro goes beyond standard textbook simulators with these features:

Multi-criteria recommendation engine

Runs all 9 algorithms on the same workload and ranks them with a weighted score of average waiting, turnaround and response time, Jain's fairness, CPU utilisation and context-switch count, with a penalty for detected starvation.

Jain's fairness index

Computes fairness J = (Σ xi)2n · Σ xi2 over each process's turnaround penalty (TATi / BTi), exposing unfair treatment of long processes.

Risk diagnostics

Root-cause explanations for the convoy effect, priority starvation and context-switch thrashing, with mitigation strategies.

Human vs scheduler

An interactive game where the user dispatches processes tick by tick and is ranked against the SRTF benchmark.

Kernel dispatcher log

A /dev/kmsg-style trace of process arrivals, dispatches, context switches, preemptions and idle periods.

Zero-lag architecture

Equipped with safety bounds (10,000 iterations per tick), debounce controls, and high-frequency animation loops running at 60 FPS in 0–1ms.

Use this 4-step sequence when presenting the project:

Step 1: Convoy effect and risk diagnostics

In Workload, click the Convoy Pitfall preset and choose FCFS. Click End in Simulate. Point out how P1 (burst 24) blocks the short jobs, then click Explain on the risk warning to show the convoy-effect explanation.

Step 2: Compare side by side in Race

Open Race and click Start race, then Play. Show how SJF/SRTF finish early while FCFS is still blocked on P1.

Step 3: Recommendation and one-click Apply

Open Recommend. Explain how the composite score is calculated, then click Apply on the winning algorithm to load it into the simulator with the same settings it was ranked with.

Step 4: Human vs scheduler and the kernel log

Open Play and schedule the processes tick by tick to try to match the SRTF benchmark. Then scroll down in Simulate to show the kernel dispatcher log.

The project is built on modular vanilla JavaScript with no runtime dependencies:

  • src/js/models/Process.js — Process Control Block (PCB) model tracking arrival, burst, remaining time, priority, queue level, timeline slices, and color tags.
  • src/js/algorithms/ — 9 individual scheduling modules: fcfs.js, sjf.js, srtf.js, roundRobin.js, priority.js, hrrn.js, mlq.js, mlfq.js.
  • src/js/engine/evaluator.js — Metrics calculator (AWT, ATAT, Response Time, CPU Util, Jain's Fairness, Convoy detection, Starvation detection, Risk engine).
  • src/js/engine/recommendationEngine.js — Multi-criteria normalized scoring engine with 4 optimization profiles and a Round Robin quantum suggestion.
  • src/js/engine/simulator.js — Step-by-step playback engine with pause, step-forward, step-backward, and speed control.
  • src/js/engine/gameEngine.js — Interactive scheduler game state machine.
  • src/js/engine/kernelSyslog.js — Builds the kernel dispatcher log events from a simulation result.
  • src/js/visualizers/ — DOM Gantt and state visualizers (ganttChart.js, stateVisualizer.js, multiRace.js).
  • src/js/app.js — Master coordinator and UI event binder.
Jain's fairness index

J(x1, …, xn) = (Σ xi)2n · Σ xi2 where xi = TATi / BTi is the turnaround penalty of process i.

HRRN response ratio

R = W + SS = 1 + WS Prevents starvation by raising the priority of long-waiting jobs (W).

Optimal time quantum heuristic

In Round Robin, the time quantum q should be chosen such that at least 80% of CPU bursts are no longer than q, minimizing context switch overhead while maintaining interactive responsiveness. The suggested q is the nearest-rank 80th percentile of the burst times, e.g. [1, 2, 3, 4, 100] → q = 4.

SRTF optimality

Shortest Remaining Time First is provably optimal for minimizing Average Waiting Time (AWT) among all scheduling algorithms, but is susceptible to starvation of long processes under continuous arrivals.
